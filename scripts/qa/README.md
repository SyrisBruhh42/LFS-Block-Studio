# Local browser qualification

These checks use disposable browser contexts, block external requests, and never open the user's normal browser profile. They do not qualify cloud services, native Minecraft, assistive technology, hardware pen/touch, or performance.

The host used for this work already supplies Playwright and Chrome. No browser automation package was added to the application. Set `PLAYWRIGHT_MODULE` to an available Playwright ESM entrypoint and `CHROME_PATH` to a test browser if they are not discoverable by the runner. `QA_NO_SANDBOX=1` is only for isolated test environments that require it; ordinary browser runs should retain the browser sandbox.

1. Run `npm run lint` and `npm test` for source contracts.
2. Run `npm run dev:local -- --port 4173 --strictPort` for the isolated real-IndexedDB contract runner: `node scripts/qa/storage-contracts.mjs`. The test page is fulfilled as blank HTML; only the imported test module runs. Database names are unique `lfs-contract-test-*` names.
3. The React save/restore race harness is `src/lib/useStudioPersistence.browser-tests.tsx`, exporting `runStudioPersistenceBrowserTests()`. Run `node scripts/qa/persistence-races.mjs` against the development server. It creates a fresh disposable browser context for each case because the hook uses the application database namespace; never import the harness in an existing user profile.
4. For full application recovery checks, freeze `npm run build`, serve `npm run preview -- --host 127.0.0.1 --port 4174 --strictPort`, then run `node scripts/qa/app-recovery.mjs`. `TEST_ORIGIN` can override this local origin; it must remain a test environment. `QA_RESULTS` overrides the default results path in `/tmp`.
5. `node scripts/qa/app-smoke.mjs` uses the development server on port 4173 for camera/edit/save/reload smoke checks. Do not edit source while it runs: hot reload can invalidate a result. Prefer the frozen build for acceptance.

Retain failed outcomes as well as the successful rerun. A generated file, successful download request, unit round-trip or passing build is not native import evidence. Software WebGL is used in the headless workflow; do not derive device capacity or frame-rate claims from these runs.

6. Run `node scripts/qa/navigation.mjs` against a frozen preview for camera/shortcut/blocked-input checks. Its receipt names exact assets and retains the initial numerical-assertion failure.
7. Run `node scripts/qa/export-drafts.mjs` against a frozen preview for diagnostic labels/downloads, sparse-bound rejection, clipboard failure, and locally intercepted AI suggestion rejection/cancellation. This runner never calls the configured provider.

8. `node scripts/qa/session-authority.mjs` tests the mounted complete document/history through the frozen App; set `QA_EXPECTED_JS` to the build asset name and `QA_RESULTS` to a fresh receipt path.
9. `node scripts/qa/resource-imports.mjs` requires `QA_EXPECTED_JS` and tests actual Library paste/import, exact source archival, isolated definitions, Undo/Redo/save/reload and malformed inputs. Use the frozen preview and disposable storage.
10. `node scripts/qa/policy-storage.mjs` runs the explicit policy-transition IndexedDB fixtures against the local development server; its receipt hashes relevant modules before and after. Unknown policy, quota/abort, competing writers, source races and predecessor corruption are included.
11. `node scripts/qa/action-outcomes.mjs` runs actual modal components with controlled callbacks against the development server. It qualifies draft/generation/result behavior, not App persistence or provider success. Keep source frozen and preserve both earlier failures and final receipts.

The enlarged persistence hook suite now includes real-controller policy transitions and original resource archival. A successful policy backend test does not mean the compatibility toggle is exposed or every App route is qualified. Closing a modal does not cancel its pending callback; test dismissal separately from operation cancellation.

12. `node scripts/qa/window-layout.mjs` mounts real shared windows and a HUD in disposable development contexts. It verifies numeric no-drag positioning/resizing, future/denied preference behavior, primary-pointer/cancel/blur ownership and ordinary toolbar buttons. Keep source stable; scoped hashes are recorded.
13. `node scripts/qa/java-export-ui.mjs` qualifies mounted export lifecycle guards with controlled producer completions. `node scripts/qa/java-export-workflow.mjs` separately checks real App downloads through an independent NBT reader. The App runner requires `QA_EXPECTED_JS`. Native game operation is not exercised.
14. `node scripts/qa/workspace-menu.mjs` requires a frozen preview and `QA_EXPECTED_JS`. It checks actual action search/focus, paged cell discovery, exact target edit and selection history, menu comfort/reflow, preference storage failures and local naming/reload. `QA_SCREENSHOT` selects a fresh local PNG path. Coarse pointer is emulated, not physical-device evidence. Themes/scaling are scoped to the new menu.
15. `node scripts/qa/project-capacity.mjs` requires a frozen preview and `QA_EXPECTED_JS`. It uses disposable 20 MiB/near 32 MiB JSON fixtures to check actual small edits/history accounting, complete payload hashes, save/reload and a real backup download reopened as a separate copy. It does not benchmark hardware, RAM, latency, rendering capacity or durable quota. It reads only the active token when checking copy activation; it does not enumerate large revision payloads.

16. `node scripts/qa/encoded-candidates.mjs` runs strict versioned candidate encoding/readback/final-transaction fixtures against the development server. It uses disposable uniquely named databases and hashes scoped source before/after. It includes invalid/unknown encodings, exact original strings, malformed source lists and tampering after verification. `recovery-storage.mjs` and `recovery-ui.mjs` separately qualify independent byte/text/source-envelope rescue. Large input fixtures are generated in disposable storage and are not user data or performance benchmarks.

17. `node scripts/qa/brush-workflow.mjs` requires a frozen preview and `QA_EXPECTED_JS`. It checks numeric/canvas brush and mirror edits, exact complete-state Undo/Redo, overlap/IDs/no-op/effects, negative layers, draft conflicts, final extent rejection, a late mouse release across an actual project switch, locked Java unit cells and save/reload. It uses actual native controls and browser mouse input; it does not run Minecraft, inspect React/App private state or mutate storage to construct outcomes. `QA_SCREENSHOT` chooses a fresh local image path. Physical pen/touch, arbitrary geometry reflection and whole-stroke history grouping remain separate.

18. `node scripts/qa/build-tool-options.mjs` checks actual native Tab order, focused control visibility and complete source preservation for the new brush/mirror form at1600/390 CSS pixels. It requires a frozen preview and `QA_EXPECTED_JS`; it does not simulate full browser/OS zoom or qualify the rest of the shell.

19. `node scripts/qa/cell-inspector.mjs` checks actual scene/numeric discovery, modeless properties, detached review and atomic Apply/Undo/Redo, grid-anchor selection with fractional authored positions, occupied destinations, draft close/resume/source conflicts, shared Oasis appearance, save/reopen and locked Java editing. It requires a frozen preview and `QA_EXPECTED_JS`. Narrow-panel checks include a usable body and native Tab focus visibility at 320 CSS pixels/200% scoped text. No App internals or storage writes construct outcomes. It does not qualify native Minecraft, physical/assistive input or the legacy shell.

20. `node scripts/qa/recipe-workspace.mjs` checks actual menu/HUD entry, command editing, exact downloaded impact, Apply/one Undo/Redo, actual clipboard paste, no-op Redo, errors/cancellation, draft/shelf/source conflicts, shared appearance and narrow native Tab, placement identities, exact `@id`/reserved names, locked intermediate rejection and save/reopen. It requires a frozen preview and `QA_EXPECTED_JS`. `QA_REVIEW_FILE` selects an archive of the actual accepted review JSON bytes. The public file-input source-switch event is an admission-boundary fixture, not a physical picker journey. No App private controller, provider, native game, physical/assistive or performance acceptance is inferred.

21. `node scripts/qa/resource-workspace.mjs` checks 18 actual resource journeys: starter/file intake and review, exact downloaded ZIP/library/placement comparison, original archival and public rescue, one Undo/Redo, actual clipboard preservation, no-op Redo, selective dependency closure and notices, source/draft conflicts, malformed/colliding files, candidate-write quota failure/retry, cancelled delayed File reads, native Tab at 320 CSS pixels/200% scoped text, fresh-storage project copy and locked/mapped placement. Use a frozen loopback preview with `QA_EXPECTED_JS`. Python 3 standard-library `studio-kit-oracle.py` independently checks the actual downloaded ZIP/CRC/JSON/SHA-256; it imports no App code. `QA_RESULTS`, `QA_SCREENSHOT`, `QA_KIT_FILE`, `QA_SELECTED_KIT_FILE`, `QA_IMPORT_REPORT_FILE`, `QA_PLACEMENT_REPORT_FILE` and `QA_SOURCE_ENVELOPE_FILE` select fresh output paths. The accepted placement report is separate from an earlier cancelled preview. Offline editing is in an already-loaded App; later reload uses loopback App assets. Service-worker cold start/update/rollback, native game, physical/assistive/device/performance and provider acceptance remain separate. The ZIP domain fixtures in `fixtures/kit-zip-interop.json` were independently generated with Python zipfile STORE/DEFLATE and seekable/nonseekable output; normal domain tests need no Python process.
